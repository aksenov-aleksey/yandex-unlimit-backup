# yandex-photo-backup

Скрипт `backup_photos.py` копирует **«безлимитные» (photoslice) фотографии** из Яндекс.Диска
в обычную папку. Папка становится видимой для публичного API / WebDAV / десктоп-клиента,
и её дальше можно синхронизировать любым удобным способом (Cloud Sync, rclone, WebDAV и т. п.).

Копирование происходит **на стороне Яндекса**: файлы не скачиваются на компьютер,
ничего не удаляется и не перемещается, лимит веб-интерфейса «не больше 500 выбранных»
не действует.

> ⚠️ Скрипт использует внутренний (не публичный) API веб-приложения и ваши cookies.
> Это не официальный способ, эндпоинты могут измениться в любой момент. Используйте на свой риск.

---

## Что делает и чего не делает

| Делает | Не делает |
| --- | --- |
| Копирует безлимитные фото в обычную папку Диска | Не скачивает файлы на диск |
| Пропускает уже скопированное (идемпотентен) | **Ничего не удаляет** |
| Работает асинхронно, серверной операцией `mpfs/bulk-async-copy` | Не трогает обычные загрузки (`nonphotounlim`), если не указан `--all-photos` |
| Умеет продолжать с места остановки | Не требует прав администратора |

## Требования

- Python 3.9+
- Зависимости из `requirements.txt`:
  - `curl_cffi` — предпочтительно (TLS-отпечаток реального браузера);
  - `requests` — запасной вариант, если `curl_cffi` не установился.

## Установка

```bash
cd yandex-photo-backup
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## Авторизация: `cookies.json`

1. Откройте https://disk.yandex.ru и войдите в аккаунт.
2. Установите в браузер расширение **Cookie-Editor**.
3. На вкладке с открытым Диском: **Export → Export as JSON**.
4. Сохраните результат рядом со скриптом под именем **`cookies.json`**.

Файл должен быть JSON-массивом в формате Cookie-Editor — скрипт берёт из него поля
`name` / `value`.

> 🔐 `cookies.json` — это фактически доступ к вашему аккаунту без пароля.
> Не коммитьте его, не отправляйте никому и не выкладывайте в публичный репозиторий.
> Файл уже указан в `.gitignore`.

Если сессия истекла, скрипт завершится с сообщением
`Куки невалидны или истекли` — просто экспортируйте cookies заново.

## Быстрый старт

```bash
# 1. Собрать список файлов. Безопасно: ничего не копируется.
python backup_photos.py --list

# 2. Пробник: скопировать ОДНО фото и показать сырой запрос/ответ.
python backup_photos.py --probe --dest /PhotoBackup

# 3. Основной прогон: сбор + копирование в щадящем режиме.
python backup_photos.py --copy --dest /PhotoBackup

# 4. Догнать неудачные (обычно после лимита параллельных копирований).
python backup_photos.py --retry-failed --dest /PhotoBackup
```

Папка назначения указывается **без** префикса `/disk` — он подставляется автоматически,
то есть `--dest /PhotoBackup` означает `/disk/PhotoBackup`.

Копирование асинхронное: файл появится в папке-назначении через несколько секунд
после ответа сервера. Дождитесь окончания скрипта перед тем, как проверять результат.

## Флаги

### Режимы работы

| Флаг | Описание |
| --- | --- |
| `--list` | Только собрать список путей. Ничего не копирует. |
| `--probe` | Скопировать один файл и вывести сырой запрос и ответ (диагностика). |
| `--copy` | Основной конвейер: сбор + копирование одновременно. |
| `--from-cache` | Не собирать заново, копировать то, что уже есть в кэше. Используется **вместе** с `--copy`: `--copy --from-cache`. |
| `--retry-failed` | Повторить только файлы из `.failed.txt`, без сбора. |

Если не указать ни один режим, скрипт просто напечатает справку.

### Что и куда копировать

| Флаг | По умолчанию | Описание |
| --- | --- | --- |
| `--dest PATH` | `/PhotoBackup` | Папка-назначение (без префикса `/disk`). |
| `--all-photos` | выкл. | Копировать все фото раздела, а не только безлимитные. |
| `--limit N` | без лимита | Скопировать не больше `N` файлов. |
| `--refresh` | выкл. | Игнорировать кэши и начать сбор заново. |
| `--no-dest-check` | выкл. | Не читать листинг папки-назначения (быстрее, но пропуски определяются только по ответу 412). |

### Настройка темпа (throttling)

У Яндекса есть лимит на число одновременных серверных копирований на аккаунт.
При превышении приходит `TooManyExecutingOperationsError`. По умолчанию скрипт работает
мягко; ускорять следует постепенно.

| Флаг | По умолчанию | Описание |
| --- | --- | --- |
| `--workers N` | `1` | Число потоков копирования. Больше 1 — агрессивнее. |
| `--copy-delay SEC` | `5.0` | Минимальная пауза между запросами копирования, общая для всех воркеров. |
| `--copy-batch N` | `10` | Файлов в одном запросе копирования. Абсолютный максимум сервера — **40**. |
| `--retries N` | `6` | Сколько раз повторять упавшие файлы. |
| `--retry-base SEC` | `10.0` | Базовая пауза перед повтором (растёт экспоненциально). |
| `--throttle-base SEC` | `30.0` | Базовая пауза при `TooManyExecutingOperationsError`. |
| `--retry-max SEC` | `600.0` | Верхняя граница паузы перед повтором. |
| `--collect-batch N` | `15` | Кластеров (дней) за один запрос сбора. |
| `--collect-delay SEC` | `1.5` | Пауза между запросами сбора. |

Дополнительно скрипт сам адаптируется: при троттлинге интервал удваивается и вся очередь
уходит в паузу, а при успешных копированиях интервал постепенно возвращается к базовому.

## Файлы состояния

Создаются рядом со скриптом, все перечислены в `.gitignore`:

| Файл | Назначение |
| --- | --- |
| `.photoslice_paths.txt` | Кэш найденных путей. Позволяет продолжать сбор после прерывания. |
| `.collect_state.json` | Чекпойнт обхода кластеров (какой день уже собран). |
| `.copied.txt` | Что уже скопировано — повторный запуск это пропускает. |
| `.failed.txt` | Что не удалось скопировать; используется `--retry-failed`. |

Удалить их можно в любой момент — скрипт просто начнёт заново (безопасно, дубликатов
на Диске не появится: копирование на занятое имя возвращает «уже существует»).

## Логика пропуска дубликатов

Скрипт проверяет три уровня, чтобы не копировать одно и то же:

1. Листинг папки-назначения (`mpfs/list`) — что там уже лежит.
2. Кэш `.copied.txt` — что уже копировали в прошлых запусках.
3. Ответ сервера 412 `resource already exists` — Яндекс сам не создаёт копии «имя (1)».

## Частые проблемы

| Симптом | Что делать |
| --- | --- |
| `Куки невалидны или истекли` | Заново экспортировать `cookies.json` из браузера. |
| `Сессия истекла (HTTP 401/403)` | То же самое — обновить cookies. |
| `CAPTCHA!` | Открыть disk.yandex.ru в браузере, пройти капчу и запустить снова. |
| `TooManyExecutingOperationsError` | Дать серверной очереди разгрузиться, затем `--retry-failed`. Помогает увеличение `--copy-delay` и снижение `--workers`. |
| `[429]` | Скрипт сам делает паузу; если повторяется часто — увеличьте `--copy-delay`. |
| Пустой результат `--list` | Возможно, на аккаунте нет безлимитных фото. Попробуйте `--list --all-photos`. |
| Ошибки при большом `--copy-batch` | Скрипт автоматически делит пачку пополам и повторяет. Значения выше 40 снижаются до 40. |

Скрипт предоставляется «как есть», без гарантий. Он работает через внутренний API
